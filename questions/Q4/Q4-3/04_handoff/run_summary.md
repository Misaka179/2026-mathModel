## 3. 模型架构

### 3.1 核心算法

**问题类型**: 两阶段随机优化 + 滚动更新

**第一阶段（日前0:00）**:
- 决策变量: 计划购电量 E_plan[t] (144个时段)
- 目标: 最小化计划购电成本
- 约束: 电力平衡（不等式）、储能约束、功率限制

**第二阶段（实际执行）**:
- 滚动调整: 6h/12h/18h三个时点更新预测并触发调整
- 动态价值函数: 指导实时充放电决策
- 紧急购电: 作为补偿项（derived variable），不参与优化

### 3.2 架构修正（v2版本）

**关键改进** (相比v1版本):

| 维度 | v1版本 | v2版本 (当前) | 改进效果 |
|------|--------|--------------|---------|
| 紧急购电定位 | 优化变量 | 补偿项 | 占比从66.7%降至0.39% |
| 电力平衡约束 | 等式 | 不等式 | 允许供电不足由紧急购电补偿 |
| 目标函数 | plan + emergency | 只有plan | 避免主动依赖紧急购电 |
| 电价使用 | 固定基准价 | 波动电价 | 符合问题要求 |

**修正理由**: 
根据GPT-RE2.md的深度分析，原架构将紧急购电作为优化变量，导致模型在低价时段（如0.0076元/kWh）主动依赖紧急购电（5倍后仅0.038元/kWh，仍比平均价便宜20倍）。修正后，紧急购电只在实际供电不足时作为补偿机制，符合"应急购电"的本意。

### 3.3 场景生成策略

**配对残差法**:
1. 选择代表性历史日（近期+相似日）
2. 提取历史日的预测误差（负载误差和光伏误差配对）
3. 应用到当前预测生成场景
4. 场景数量: 1-30个（数据积累动态增加）

**场景代表性**:
- 捕捉预测不确定性
- 保持负载与光伏误差的相关性
- 覆盖不同日类型（低负载/高负载星期）

### 4.2 日优化流程

**每日标准流程** (334天循环):

```
Day N (例如: 2025-02-01)
├─ 1. 生成场景 (1-30个)
│  ├─ 选择历史相似日
│  ├─ 计算配对残差
│  └─ 生成预测场景
│
├─ 2. Stage 1优化 (日前0:00)
│  ├─ 决策: E_plan[t] (144时段)
│  ├─ 目标: min 计划购电成本
│  └─ 约束: 电力平衡、储能、功率限制
│
├─ 3. 构建动态价值函数
│  ├─ 场景模拟: 30个场景 × 144时段
│  ├─ 动态规划: 反向递推
│  └─ 生成决策表: V[t, soc]
│
├─ 4. 实际执行 (144时段)
│  ├─ 6h更新: 检查预测变化 → 触发调整
│  ├─ 12h更新: 检查预测变化 → 触发调整
│  ├─ 18h更新: 检查预测变化 → 触发调整
│  ├─ 实时决策: 根据价值函数选择充放电
│  └─ 紧急购电: 缺口补偿 E_emergency[t] = max(0, 缺口)
│
└─ 5. 记录结果
   ├─ E_plan[144], E_adjust[144], E_final[144]
   ├─ E_charge[144], E_discharge[144], E_storage[144]
   ├─ E_emergency[144]
   └─ Z_plan, Z_adjust, Z_emergency, Z_total
```

### 4.3 关键时点处理

**Stage K调整触发条件**:

| 时点 | 检查项 | 触发条件 |
|------|--------|---------|
| 6:00 | 光伏预测变化 | 变化>5% 且 SOC<50% |
| 12:00 | 光伏预测变化 | 变化>5% 且 SOC<50% |

**调整策略**:
- 预测上调 → 减少购电调整
- 预测下调 → 增加购电调整
- SOC过低 → 紧急补充购电
