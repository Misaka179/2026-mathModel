## 2. 数据处理流程

### 2.1 计费期间确定

**关键决策**: 问题要求计算2-12月运营成本

- **1月份（31天）**: 仅用于模型参数估计和日类型识别，**不计入成本**
- **2-12月（334天）**: 正式计费期间，从2025-02-01至2025-12-31

**理由**: 
1. 滚动预测模型需要历史数据进行参数估计
2. 日类型识别（低负载/高负载星期）基于1月1-14日数据
3. 与问题三保持一致（问题三也是334天计费）

### 2.2 波动电价数据处理

最大值: 1.7936 元/kWh

### 2.3 日类型识别

基于1月1-14日的负载数据，识别低负载和高负载星期：

| 星期 | 平均日电量 | 分类 |
|------|-----------|------|
| Friday | 81,685 kWh | 低负载 |
| Saturday | 81,751 kWh | 低负载 |
| Monday | 126,904 kWh | 高负载 |
| Tuesday | 127,181 kWh | 高负载 |
| Wednesday | 128,034 kWh | 高负载 |
| Thursday | 131,235 kWh | 高负载 |
| Sunday | 134,419 kWh | 高负载 |

**说明**: 周五和周六为低负载日（可能因工业负荷降低），其余为高负载日。

### 2.4 场景生成数据处理

**历史相似日选择**:
1. 近期候选池: 最近30天
2. 相似日候选池: 31-365天前的同类型星期
3. 特征匹配: 基于日总电量、光伏总量、净负载方差等6维特征
4. 场景数量: 30个（动态调整，数据不足时使用确定性预测）

**场景生成方法**:
- 配对残差法: 历史日的预测误差（负载误差和光伏误差配对）
- 应用到当前预测: `场景值 = 当前预测 + 历史残差`
